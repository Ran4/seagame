# Shanty voice tracks not perfectly in sync

The per-voice shanty tracks (male_1, male_2, female_1, female_2) generated by the sea shanty pipeline are not perfectly in sync rhythmically. Each voice is recorded line-by-line and time-stretched to match the fastest voice, but they still drift slightly.

## Impact

- Random offset playback (planned for natural feel) would make it worse, not better
- Layering multiple slightly-out-of-sync tracks sounds messy at best

## Blocked features

- **Random playback offset** (50-200ms per voice): wait until tracks are properly synced
- **Singing ability system**: crew with higher singing skill could get better sync — but meaningless until base tracks are aligned

## Possible fixes

1. Improve time-stretch accuracy in the generation pipeline (tighter atempo matching)
2. Use a single reference track and align others to it via cross-correlation
3. Generate all voices in a single API call if OpenAI supports multi-voice output
4. Post-process with forced alignment (e.g. gentle/aeneas) before assembly
